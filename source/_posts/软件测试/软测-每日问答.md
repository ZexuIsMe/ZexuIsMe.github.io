## 怎样的流程算是基本流，什么算是备选流，什么又算是异常流？
A：按照一般流程做完的一条龙服务就是基本流，
比如登录，
- 第一步：输入用户名，
- 第二步：输入密码
- 第三步：点击登录

登录调用登录接口传递数据，后端检测数据，数据库中存在该用户且密码与该用户的密码一一对应，返回前端200code
前端接收到接口响应的200code表示该用户可以登录，于是离开用户登录页面，跳转到首页位置
这个过程中没有任何额外的操作，也没有出现异常情况，即为基本流
什么又算是备选流呢？在基本流的基础上进行的拓展，在经历一番波折但最终的结果导向是符合预期结果的流程算是备选流
什么又算是异常流呢？在基本流或备选流的基础上进行的拓展或该流程出现意外情况，比如，用户名输入错误，其他均已填写，点击登录，系统提示：用户名或密码错误，
只要不在基本流和备选流的预期范围内的异常行为皆可算作异常流

## 简述一下黑白灰盒的区别
黑：完全不考虑系统内部结构和代码实现，仅通过输入输出验证功能是否符合需求，**不依赖代码，适合测试人员（非开发）执行**；更贴近用户实际使用场景。
白：完全知晓系统内部代码、逻辑结构和实现细节，基于代码逻辑设计测试用例。**能发现代码级缺陷（如逻辑错误、死循环）**；测试更彻底（覆盖代码路径）。
灰：部分了解系统内部结构（如接口设计、数据库结构），但不深入代码细节，结合黑盒和白盒的思路。**兼顾功能验证和内部逻辑，测试效率更高**；无需深入代码，成本低于白盒。

## 描述一下INNER JION、LEFT JOIN、RIGHT JOIN
- INNER JOIN：全匹配，只匹配符合桥梁的数据；
- LEFT JOIN：左连接：以左表为主，左表全额输出，若右表不存在匹配记录则显示NULL作为填充参数
- RIGHT JOIN：右连接：以右表为主，右表全额输出，若左表不存在匹配记录则用NULL作为填充参数

## TCP和UDP的区别？

tcp是基于连接的可靠的协议，而udp发送之前不需要建立连接，但是udp的传输效率高

## （Python）浅拷贝、深拷贝的区别？

浅拷贝：拷贝层级只有一层，若元素是只读对象，则修改不会影响源对象；若元素是可变的，如列表，则修改会影响源对象
深拷贝：拷贝层级是所有层级，与源对象完全脱离引用，无论怎么就该都不会影响源对象

```python
import copy

# 定义一个 变量x，赋予list对象
x = list([1, 2, 3, [4, 5]])
# 定义 变量y 并将 x 赋值给 变量y
y = x.copy()

print("x == y：", x == y) # 输出：True
print("x is y：", x is y) # 输出：False
print("-"*40)

y[0] = 100
y[-1].append(6)
y.append(1)
print(f"x：{x}") # [1, 2, 3, [4, 5]]
print(f"y：{y}") # [100, 2, 3, [4, 5, 6], 1]
print("-"*40)

# 深拷贝：copy.deepcopy(target)
z = copy.deepcopy(x)
z[0] = 200
z[-1].append(10)
print(f"x：{x}") # [1, 2, 3, [4, 5, 6]]
print(f"z：{z}") # [200, 2, 3, [4, 5, 6, 10], 1]
```

通过这段代码进一步验证了前面对深浅拷贝描述的正确性

- 通过环境变量 `PYTHONPATH` 配置的路径

## python使用什么符号实现语句的嵌套关系？

使用冒号和缩进实现语句的嵌套关系

冒号：用于标记一个代码块的开始，通常放在条件判断、循环、函数以及类定义等语句的末尾
缩进：用于表示代码块的范围，缩进的部分属于该代码块，形成嵌套关系，通常情况下以4个空格作为标准缩进

```python
for i in range(3):  # 冒号标记循环代码块的开始
    print(f"外层循环：{i}")  # 缩进表示属于外层循环
    if i > 0:  # 冒号标记条件代码块的开始
        print("  内层条件：i大于0")  # 更深的缩进表示嵌套在条件中
```

## （Python）阅读下面这段代码，其输出结果是：

```python
def func_1(item:str, x:list=[]):
   x.append(item)
   return x
print(func_1('1')) # ['1']
print(func_1('2')) # ['1', '2']
print(func_1('3')) # ['1', '2', '3']
```

这是 Python 中默认参数的“可变默认值陷阱”，本质是因为默认值在函数定义时仅初始化一次，对于列表、字典等可变对象需特别注意。

函数的缺省值在函数定义时创建的，不会每次调用时重新创建。若不指定传入的实参 x，则调用默认参数 x 且指向同一个列表对象

每次调用 func_1 且未传入 x 时，都会复用这个默认列表，append 操作会累积到同一个列表中。

## 描述一下瀑布模型以及瀑布模型的作用。

瀑布模型是一种流水式的模型，一步一个脚印，从计划到需求分析到概要设计到详细设计到编码阶段到单元测试到集成测试到系统测试到验收测试最后到运维阶段，是一个完整的软件生命周期的过程。

它将测试阶段拆分成先单元测试，接着集成测试，再系统测试最后验证测试四个阶段。

瀑布模型的缺点也是其优点，它每个阶段只做对应的事情。

## （MYSQL）drop table、truncate table 和 delete 三者的区别？

【drop table】 用于数据表的删除 `drop table 表名`
【truncate table】 用于数据表的数据的删除 `truncate table 表名`
【delete】 用于对数据进行删除 `delete from 表名 where 条件`

三者之间的区别在于：

drop table 的操作是直接抹除掉数据表，从数据库中消失；
delete 操作是删除指定的行数据
truncate table 操作将数据表删除掉并重新创建一次，约等于将数据表的数据全部清空

## （Web测试）描述一下 SQL 注入，其特点是什么？

SQL注入是一种常见的安全漏洞，攻击者通过在用户输入的参数中插入恶意SQL语句，如单引号，或 `' or 1==1 #` ，欺骗数据库执行非预期操作的攻击方式

其最主要的特点就是对可进行数据交互的输入进行SQL注入，若前端或后端都没有相应的内容检测，那么SQL注入极大概率是会被执行的，进而可能导致系统崩溃，数据泄密等严重软件事故

> 利用前端或后端对输入校验不足的缺陷，将SQL代码输入到查询中；
> 攻击方式隐蔽，常通过表单输入，URL参数等途径实施；
> 危害严重，可能泄露敏感信息或破坏数据库完整性；

## （Web测试）描述一下脚本攻击，其特点是什么？

又叫跨站式脚本攻击XSS，包括通过在网页中输入含有恶意的JS脚本文件，当用户访问受影响页面时，脚本就会在用户浏览器中执行，达到窃取信息或控制用户行为的目的

对数据交互校验薄弱的地方，写入恶意脚本文件代码，通过数据的交互，将代码存入服务器，若该数据信息会用于前端的数据展示，那么脚本文件大概率是会被渲染并执行的。

## 在自动化测试中，如何解决 “页面元素定位不稳定” 的问题？

元素定位不稳定的原因：
1. 页面结构发生变化，所以为了解决该问题可使用精确定位的ID或者XPATH的相对路径进行定位或者多种属性组合配合定位也能缩小定位范围；
2. 页面还未加载就执行定位，所以可设置合理的等待机制，比如
   - sleep(.5): 设置一个固定的等待间隔
   - 隐式等待：webdriver.implicitly_wait(5); 是全局设置等待时间，对所有元素都有效
   - 显示等待：
```python
# Selenium显式等待示例
from selenium.webdriver.support.ui import WebDriverWait
from selenium.webdriver.support import expected_conditions as EC

# 等待10秒，直到按钮可点击
submit_btn = WebDriverWait(driver, 10).until(
    EC.element_to_be_clickable((By.ID, "submit-btn"))
)
submit_btn.click() 
```

## （MySQL）MySQL语句排错：

```sql
SELECT 
    user_id,  
    SUM(order_amount) AS total 
FROM orders
WHERE
    (create_time BETWEEN '2424-05-01' AND '2024-05-31') AND
    pay_status = 1
HAVING SUM(order_amount) > 1000
GROUP BY user_id 
```

正确的

```sql
SELECT 
    user_id,  
    SUM(order_amount) AS total 
FROM orders
WHERE
    (create_time BETWEEN '2024-05-01 00:00:00' AND '2024-05-31 23:59:59') AND
    pay_status = 1
GROUP BY user_id
HAVING SUM(order_amount) > 1000
```

## （MySQL）纠错：以下 SQL 语句尝试查询年龄大于 18 的用户姓名，找出错误并修正

```sql
SELECT name FROM users WHERE age > 18 ORDER age DESC
```

错误1：排序关键字不完整，应是`ORDER BY age DESC`
错误2：缺少语句结束标识`;`

```sql
SELECT name FROM users WHERE age > 18 ORDER BY age DESC;
```

## （Python）纠错：以下代码尝试计算 1 到 10 的和，找出错误并修正

```python
sum = 0
for i in range(10)
    sum += i
print('1~10  SUM：{sum}')
```

错误1：`range` 取值范围为闭区间`[0, 9]`，它有10个数但数字10不在区间范围内
错误2：for 语句缺少`:`
错误3：打印输出使用了格式化输出，但是没有使用前缀`f`

```python
sum = 0
for i in range(1, 11):
    sum += i
print(f'1~10  SUM：{sum}')
```
