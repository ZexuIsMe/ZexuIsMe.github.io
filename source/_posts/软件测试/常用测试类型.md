测试类型是不固定的，根据需要的不同，就会有不同的测试类型

| 测试     | 描述                                                                                       |
|--------|------------------------------------------------------------------------------------------|
| 健壮性测试  | 模拟用户的各种异常使用，检验产品的防错性、容错性；<br/> 也叫鲁棒测试，robust                                             |
| 易用性测试  | 针对产品易用性的测试，主要由美工、用户进行测试                                                                  |
| 强度测试   | 测试系统在正常负载条件下长期运行的可靠性                                                                     |
|        | 在一定的负荷条件下，在较长时间跨度内的系统连续运行给系统性能所造成的影响                                                     |
| 容量测试   | 关注系统能够处理的最大数据量或并发用户数                                                                     |
|        | 容量测试目的是通过测试预先分析出反映软件系统应用特征的某项指标的极限值（如最大并发用户数、数据库记录数等），系统在其极限值状态下没有出现任何软件故障或还能保持主要功能正常运行。 |
|        | 容量测试是面向数据的，并且它的目的是显示系统可以处理目标内确定的数据容量。                                                    |
| 性能测试   | 测试系统在正常工作负载下的响应时间、吞吐量、资源消耗情况等指标                                                          |
| 安全性测试  | SAL注入：通过在搜索框中输入sql语句的部分内容来改变原来的查询功能，比如从商品搜索变陈管理员用户名密码的搜索跨站脚本攻击                           |
| 安装测试   | 对产品的安装、升级和卸载进行的测试；<br/> 属于可移植性的易安装性特性                                                    |
| 搬迁测试   | 检验产品替换老产品时是否能完整正确的移植老产品的功能和数据的测试                                                         |
| 容灾测试   | 检验产品出现灾难时的承受能力，以及修复产品的能力的测试                                                              |
| 互操作性测试 | 检验软件和其他软件、硬件之间的调用，数据传递等情况的测试                                                             |
| 兼容性测试  | 检验产品在要求的各种运行环境中能否和其他要素共同运行的测试                                                            |
| 可靠性测试  | 主要针对产品的可靠性中的成熟性进行的测试，叫做可靠性测试                                                             |
| 负载测试   | 验证要检验的系统的能力最高能达到什么程度                                                                     |
|        | 在一定的工作负荷下，系统的负荷及响应时间                                                                     |

> 分割线

## 功能测试

## 性能测试

【按平台分】 前端性能测试、后端性能测试
一般情况下常说的性能测试专指**后端**性能测试。

【从测试关注点分】 基准测试、负载测试、压力测试、容量测试、配置测试、可靠性测试

## UI测试 （User Interface）

检验软件和使用者之间交互操作、传递信息的测试

也会检测产品的美观性、易于学习、易于使用的也行

UI分类：CLI（命令行接口）、GUI（图形化用户接口）

## 压力测试

是破坏性测试，但是现在一般情况下会认为是性能测试

- 超出预期负载

巨量情况下做的负载测试是压力测试，但常说的压测是指基准测试

## 负载测试
是不同情况下的基准测试，比如一辆车，在空车，车载1吨、车载2吨、车载5吨等等情况下
负载越大，性能越低，越容易出错

不追求负载、压力，比如登录，某网站20万用户全部登录，不管登录过程的耗时
