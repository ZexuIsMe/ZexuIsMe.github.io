- DQL（数据**查询**语言）：查询数据的数据，是学习的重点和难点；代表性关键字【select】
- DML（数据**修改**语言）：改变数据库的数据，次重点；代表性关键字【insert、update、delete】
- DDL（数据**定义**语言）：用于定义数据的结构，次次重点；代表性关键字【create、alter、drop】
- DCL（数据**控制**语言）：用于控制访问权限，通常由DBA（数据库管理员 Database Administrator）来操作；代表性关键字【grant、revoke】

## 数据类型：数字

- int：`int(11)`
  - type: 整型
  - 11：表示 int 类型最大位数，其取值区间为 [1, 11]
  - 如果位数不够，如 100，则不足的部分会由0填充：00000000100

- float：`float(m,d)`
  - type: 单精度浮点型
  - m：表示长度或者位数
  - d：表示小数位数（小数位数是算在长度内的）
  - Eg: `float(6,2)`：表示该浮点数最大长度位6，且有两位小数，整数长度为 m-d, 即 4 位
  - 若长度超出6，如 12345，则不会被允许添加

- double：`double(m,d)`
  - type: 双精度浮点型
  - m、d 同 float 一样
  - Q：单精度与双精度有什么区别？

    能定义的长度不同，单精度为4个字节（7位有效数），双精度为8个字节（16位有效数）

- decimal: `decimal(m,d)`
  - type: 定点型
  - m、d 同 float 一样
  - Q：浮点型与定点型的区别？

    浮点型是<mark>近似值</mark>数据类型，存在误差，如 10/3 ≈ 3.33333 在数据库中可能是 3.33335。

    **定点型以字符串的形式存储数据，解决了浮点型带来的误差问题**。

    故，如果对数据的完整度十分敏感，那么采用定点型数据类型是合适的。

## 数据类型：字符

- char: `char(m)`
  - type: 字符串
  - m：表示字符串的长度
  - 一种固定了长度的，如果字符不够，则会用空格替代的字符串数据类型
  - 如一个长度为5的 char 字段，要写入 '汉字' > '汉字xxx'（x 在这里表示空格占位）
  - 同 int 一样，若超出长度，则无法写入

- varchar: `varchar(m)`
  - type: 字符串
  - m：表示字符串的长度
  - 不固定长度的字符串数据类型
  - 如一个长度为5的 varchar 字段，要写入 '汉字' > '汉字2'；其中2表示该字符的长度
  - 同 int 一样，若超出长度，则无法写入
  - Q：char 与 varchar 的区别？

    char是固定长度的，可以有更快的读取速度，如固定长度的身份证之类的
    varchar 是不固定长度的，相对于 char 而言，节约开销，比如名字，就适合用 varchar

- enmu: `enmu('1', '2', ...)`
  - type: 枚举型
  - 设置字段的取值范围

- add: 添加字段 `alter table 表名 add 字段1 数据类型;`
- rename: 修改数据表名字 `alter table 表名 rename 新表名; `
- change: 改变数据表字段信息 `alter table 表名 change 旧字段 新字段 数据类型;`
  - Eg: 将 name 更改为 rename:  `alter table 表名 change name rename varChar(20);`
  - 即没有做修改的部分也要完整的输出
- drop: 删除字段 `alter table 表名 drop 字段;`

Q：`MODIFY` 和 `CHANGE` 的区别？

共同点：均可以修改字段类型
不同点：`MODIFY`不能修改字段名；`CHANGE`可以修改字段名

## 约束

- NOT NULL：字段不允许为空
- UNIQUE：字段不允许重复
- PRIMARY KEY：主键，不为空+不允许重复的组合
- DEFAULT：设置字段默认输出
- FOREIGN KEY：外键，用的少
- CHECK：保证字段中的值符合指定的条件。
- INDEX：用于快速访问数据库表中的数据

### 约束：主键 PRIMARY KEY

主键：不允许重复、不允许NULL；一张表至多一个主键

- 单主键：`学号 INT PRIMARY KEY`
- 联合主键：几个字段列的组合而成，
```sql
CREATE Table 班级_学生表(
    班级号 INT
,   学号 INT
,   姓名 VARCHAR(10)
,   PRIMARY KEY(班级号, 学号)
);
```

### 约束：外键 FOREIGN KEY

语法：FOREIGN KEY(当前表即将成为外键的字段名) REFERENCES 外键目标数据表(目标数据表的主键字段名)

- FOREIGN：foreign
- REFERENCES：references

```sql
CREATE TABLE A (
    c1 INT PRIMARY KEY,
    c2 VARCHAR(20)
);

CREATE TABLE B (
    cc1 INT,
    cc2 VARCHAR(5),
    cc3 INT,
    FOREIGN KEY(cc3) REFERENCES A(c1)
);
```

注意，如果删除表，那么应该先删除数据表B，再删除数据表A

一般情况下不太会用外键，因为外键会影响SQL运行速度，若用户量没那么多的，可以考虑

### 约束：CHECK

> 保证字段中的值符合指定的条件。

```sql
CREATE TABLE Products (
    ProductID INT NOT NULL PRIMARY KEY,
    ProductName VARCHAR(100) NOT NULL,
    Price DECIMAL(10, 2) CHECK (Price >= 0)
);
```

也就是字段录入的前置条件

### 约束：INDEX

> 用于提高查询性能的数据库对象，它通过创建数据的快速查找结构，避免全表扫描，从而加快数据检索速度。

语法：`CREATE INDEX idx_user_id ON orders(user_id)`

- `CREATE INDEX`：创建索引的关键字，用于告诉数据库对象
- `idx_user_id`：给索引起的名字，命名规则一般为`idx_字段名`，方便识别索引对应的字段
- `ON orders`：指定要创建索引的表名，这里是 orders 数据表
- `user_id`：指定要为那个列创建索引，这里是 `user_id` 字段需要用到INDEX

如果涉及不允许重复，那么语法为：`CREATE UNIQUE INDEX`

如果涉及多个目标，比如经常需要查询 "2023 年用户 ID=10086 的订单
`CREATE INDEX idx_user_time ON orders(user_id, order_time)`
这个索引会先按user_id分组，每个分组内再按order_time排序，进一步加快多条件查询。

什么时候需要用到索引呢，超大数据量的情况下，如果有100万条数据，要从中找到制定的数据，

正常情况下是`Select * From table Where user_id=123;` 查询过程可能需要等待2~3秒，或许更久的情况

在这种情况下，使用索引会极大的增加查询速度。

## limit

- `limit N` 返回 N 条记录，默认为前 N 条；
- `offset M`：跳过 M 条记录，默认为 0 ，单独使用不起作用；
- `limit N,M`：相当于 `limit M offset N`，从第 N 条记录开始，返回 M 条记录；

```sql
/*---返回指定数量记录：limit---------------------------------------*/
## 取前两条记录，只要设备ID
select device_id from user_profile limit 2;
```

**Q：写语句时常遇到“24岁以上”这样的条件，到底是大于等于还是只大于呢？**

A：是只大于的，如果是大于等于，应该是“24岁及以上”

## IS NULL、IS NOT NULL

语法：`目标 IS NULL`

`NULL`值无法通过常规的逻辑运算符判断，也就是无法使用如 `age=NULL` 这样的写法;

那么该如何判断空值呢？

Eg: 现在运营想要对用户的年龄分布开展分析，在分析时想要剔除没有获取到年龄的用户，请你取出所有年龄值不为空的用户的设备ID，性别，年龄，学校的信息。

```sql
SELECT device_id,gender,age,university
    FROM user_profile
    WHERE age IS NOT NULL;
```

**过滤空值的三种方法**：
(1) Where 列名 is not null
(2) Where 列名 != 'null'
(3) Where 列名 <> 'null'

## 组合查询：Union

- 会自动做去重操作
- 输出字段按UNION左侧的字段输出
- 组合查询时，前后两表用于显示的字段数据类型必须一致
- 只看数据类型不看长度，比如varchar(10)和varchar(20);

Q：那你知道去重的是什么样的数据吗？和distinct有区别吗？

A：UNION是针对**行**的去重，去掉的是一模一样的行数据，distinct是针对**字段**的去重

| aid | aName |
|-----|-------|
| 1   | Alice |
| 2   | Simon |

| bid | bName |
|-----|-------|
| 1   | Alice |
| 2   | Bob   |

```sql
SELECT aid, aName FROM aaa
UNION
SELECT bid, bName FROM bbb;
```
因为 a、b 两表的 Alice 数据一模一样，会被去重；
若 A 表 Alice 的 aid 参数为 3，那么当执行 UNION 组合查询的时候，就不会被去重。

如果不希望主动去掉相同数据行，可使用 `UNION ALL`

Q：组合查询中的ON和WHERE的区别？
A：ON子句用于定义连接条件；WHERE是用于过滤连接后的结果集

## 通配符

- %：匹配多个字符；`北京%`表示北京大学，北京医院，北京车站等等
- _：匹配一个字符；如上即可明白
- 正则：https://www.runoob.com/sql/sql-wildcards.html
  - `WHERE name REGEXP '^[GFs]'`: 名字以 G、F、s开头的
  - `WHERE name REGEXP '^[A-H]'`: 名字在 A~H 这个区间内开头的
  - `WHERE name REGEXP '^[^A-H]'`: 不以 A 到 H 字母开头

## 聚合函数

- count(): 统计
- max(): 找出最大值
- avg(): 平均值

在没有分组情况下，查询的返回，始终只有一行数据。

### 聚合函数：COUNT

- `COUNT(*)`：统计行数；
- `COUNT(字段)`：只统计非空的；
- `COUNT(DISTINCT 字段)`：字段去重后再统计，还是会排空，空不算在统计范围内

### 聚合函数：MAX

Eg: 运营想要知道复旦大学学生gpa最高值是多少，请你取出相应数据

```sql
SELECT MAX(gpa) FROM user_profile WHERE university='复旦大学';

# 输出字段：MAX(gpa)
## 配合AS输出预期字段
SELECT MAX(gpa) AS gap FROM user_profile WHERE university='复旦大学';
```

### 聚合函数：AVG

- 求平均值
- **不会出现在 WHERE 中**，出现即为语法错误；
- **SELECT 中一旦使用过聚合函数后，该SELECT查询语句就不要再添加其他查询字段列，以及计算或函数计算。**
- 严格截断小数 `TRUNCATE(m, n)`; 不会四舍五入；
如果需要四舍五入可以考虑：ROUND(m,n) 或者 FORMAT(m,n)
  - m: 浮点数
  - n: 小数位数

## 分组：GROUP BY

- 按类别分组查询数据信息
- 会压缩记录，与聚合函数类似，所以，分组后就不要再添加其他查询字段列，以及计算或函数计算。
- 非要有表中字段，只能是GROUP BY的目标字段

```sql
-- 不统计信息就用去重分组
SELECT DISTINCT bm FROM t_yg;

-- 要统计某部门，比如最高薪资，最低薪资，部门有多少人等等操作
SELECT bm, COUNT(bm) AS 部门人数
FROM t_yg
GROUP BY bm;
```

## 转移查询：INSERT INTO SELECT

- 将一个表的数据复制到另一个表
- 目标表中任何已存在的行都不会受到影响

注意：【目标表中任何已存在的行都不会受到影响】是有前提的

Q：前提是什么？

A：需避开表的约束

若为空表，那么无需在意，只需将目标字段转移过来即可，
若不为空表，则需要注意，如主键是否重复了，如果主键数据不需要，则从复制字段中剔除。

```sql
Drop TABLE IF EXISTS aaa;
CREATE Table IF NOT EXISTS AAA(
    aid int PRIMARY KEY AUTO_INCREMENT,
    aName VARCHAR(11)
);
INSERT INTO AAA(aName) VALUES('张三'), ('李四');

CREATE TABLE CCC(cid int PRIMARY KEY AUTO_INCREMENT, cName VARCHAR(20));
```

- 空表： `INSERT INTO ccc SELECT * FROM aaa;` 会将aaa表数据原封不动的输入到ccc表
- 非空表：若继续执行空表时的操作，则会报错，因为主键约束，所以需要避开，那么：`INSERT INTO ccc (cName) SELECT aName FROM aaa;` ，执行完毕后，表中将多两出条数据，印证了“目标表中任何已存在的行都不会受到影响”
