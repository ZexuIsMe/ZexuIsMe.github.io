局域网

  • 是企业、组织内部网
  • 相对封闭的网络环境。
  • 防火墙保护，由权限控制

目的：使企业或组织内部的秘密或敏感信息受到保护

网络的结构

CS: 客户端到服务器
BS：浏览器到服务器，浏览器本身不是，网页是
P2P：点对点

Q：C/S与B/S区别？

  1. CS需要下载安装，BS不需要，打开即可用
  2. CS升级维护很高，BS维护成本不高
  3. CS对客户端的性能要求高，BS对服务器的性能要求高
  4. CS操作业务流程复杂，BS操作简单，以鼠标为主
  5. CS是非标准的，是可定制化的，BS是标准化，个性化程度低
  6. CS保密安全度高，BS的保密安全程度低
  7. CS响应快，BS的响应速度受网速，浏览器性能影响
  8. CS兼容性差，BS兼容性高

WEB的工作原理

一次请求响应的过程：

  • 客户端向服务器发送请求，（请求数据）
  • 服务器接收请求数据，并处理，得到结果
  • 服务器将结果返回给客户端（响应数据）
  • 客户端接收响应的数据，将数据解释到浏览器中

URL地址

URL是统一资源定位符

协议名称://主机名:端口号/路径/文件名.扩展名?参数名=参数值

域名： IP的别名

协议类型：

HTTP

  • 抓包：默认，抓到包是明文
  • 端口号默认80，可省略

HTTPS

  • 抓包需要CA验证，即便抓到大概率是乱码，需要解码工具
  • 端口号默认443，可省略

端口号

GET、POST

区别？

GET参数在ULR当中，POST参数在被封装在请求体中，不在URL
GET安全性低，POST相对安全
GET有大小限制（1-2kb）,POST无大小限制

网络模型：OSI参考模型的 7层模型

  1. 应用层：提供应用程序间通信
    通过取件码取得包裹
  2. 表示层：处理数据格式、数据加密
    向客户发送取件码
  3. 会话层：建立、维护、管理会话
    菜鸟驿站接收包裹
  4. 传输层：建立端到端的连接
    分拣完毕后，向目标地址派送包裹
  5. 网络层：负责寻址和路由选择
    分拣中心根据目标分拣数据地址
  6. 数据链路层：提供介质访问、链路管理
    快递点打包数据，发往分拣中心
  7. 物理层：位流传输
    准备好数据，前往快递点寄送

Q：TCP与UPD区别？

TCP协议：可靠的传输控制协议
UDP：用户数据包协议/数据报传输控制协议

TCP：有短联接、可靠的、有序的、端到端的、安全的、全双工的
UPD：无联接、不可靠的、无需的、不安全的、传输速度快

本质区别在于有无三次握手和挥手，握手和挥手的目的就是为了建立安全数据传输。握手和挥手的过程需要消耗资源，导致传输速度在一定程度下降变慢。

Q：界面中五颜六色的背景块分别是什么意思？
A：每个颜色块都有属于自己的含义，一般情况下，黑底的属于情况比较糟糕的，比如请求资源失败这样的，剩下的基本是安全可用的；即背景色越深越糟糕。

TCP抓包时，是按先来后到的顺序记录，因为是全双工的

Q：那么，请问什么事全双工？单双工又是啥？
单双工：单项通道，单程火车票，比如广播
全双工：双向通道，可往返的火车票，可分为半双工和全双工。

  • 其中半双工，比如对讲机，可以接收，也能通话，但是当你通话的时候，无法接收。
  • 全双工：如电话，既能接收信息，也能发送信息

Q：抓包的时机？
一旦测试中发现BUG，需要定位BUG的时候，才需要抓包，将抓包的结果发送给开发处理

Q：Fiddler抓包遇到证书相关问题怎么办？
A：菜单栏 Tools》Options》Https选项卡》Actions按钮》点击：Reset All Certificates》后续一直点确认即可，该操作是删除旧证书，安装新证书

有短联接：三次握手、四次挥手


三次握手
客户端向服务器发送SYN，请求建立连接,等待服务器响应
》服务器接收到SYN后，为了表示自己收到了SYN，返回ACK确认信息，表示已做好联接准备
》客户端收到服务器发回来的SYN、ACK确认信息。客户端因此确认服务器已准备好联接
》客户端向服务器发送客户端已准备好的ACK信息，
》至此三次握手完成。

  • 三次握手的核心是 “双方互相确认对方的收发能力”，是 TCP 协议实现可靠传输的基础
  • 三次握手仅在建立新连接时执行一次，而非每次请求都重复

Q：为什么要三次握手？

第一次握手：客户端确认 “服务器能收到我的消息”。
第二次握手：服务器确认 “客户端能收到我的消息，且客户端能发消息给我”。
第三次握手：客户端确认 “服务器能收到我的消息，且服务器能发消息给我”。
三次握手后，双方才能确保双向通信通道的可靠性，避免因网络延迟导致的 “失效连接请求” 被误处理（例如客户端早先发的 SYN 因延迟到达服务器，此时客户端已放弃连接，但服务器仍误以为是新请求）


四次挥手
客户端打算断开连接，向服务器挥手（FIN），说自己要离开了（ACK）
》服务器看到挥手信息（FIN）后，点头示意并返回ACK确认信息
》同时，服务器向客户端也表示自己要断开连接，向客户端挥手（FIN），说下次再见（ACK）
》客户端看到挥手信息（FIN）后，点头示意并返回ACK确认信息。
》至此四次挥手完成。

  • TCP 四次挥手是断开连接时双方确认资源释放的过程，确保数据传输完整

Q：为什么要四次挥手？

  • 前两次挥手：客户端通知服务器 “我要断了”，服务器确认 “收到，我知道了”（但服务器可能还有数据要发，不能立即关闭）。
  • 后两次挥手：服务器处理完数据后，通知客户端 “我也断了”，客户端确认 “收到，结束”。
  • 四次挥手的核心是允许双方分别独立关闭连接（半关闭状态），确保任何一方未发送完的数据能继续传输，避免数据丢失。

简单记忆状态码：1XX, 2XX, 3XX 都是正常的；4XX，5XX都是异常的

系列 状态码 描述
100 服务器收到请求，需要请求者继续执行操作
200 200 请求成功
300 重定向
400 404 NotFound，客户端找不到对应的资源
500 服务器端响应有问题
