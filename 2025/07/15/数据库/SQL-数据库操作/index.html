  • DQL（数据查询语言）：查询数据的数据，是学习的重点和难点；代表性关键字【select】
  • DML（数据修改语言）：改变数据库的数据，次重点；代表性关键字【insert、update、delete】
  • DDL（数据定义语言）：用于定义数据的结构，次次重点；代表性关键字【create、alter、drop】
  • DCL（数据控制语言）：用于控制访问权限，通常由DBA（数据库管理员 Database Administrator）来操作；代表性关键字【grant、revoke】

注意事项：

  • SQL所有标点符号都应该是英文输入法状态下输入的
  • 运行前，要选中执行的指令，明确你的执行目标；
  • Linux 中，数据库库名区分大小写，Windows 中不区分大小写；
  • 表名，关键字是不区分大小写的；
  • NULL不是’’，NULL是NULL，’’是字符长度为零的字符，也不等价于数字零；
  • DBS=DBMS+DB

命名规则：

  • 字符、数字、下划线组成
  • 第一个字符不能是数字，也不能是汉字

数据类型：数字

  • int：
    在MYSQL中可以这样int(11)，其次若字段没有ZEROFILL，这个数字仅为客户端显示提示，不影响实存储和计算

    • type: 整型
    • 11：表示 int 类型最大宽度，其取值区间为 [1, 11]
    • 如果位数不够，如 100，则不足的部分会由0填充：00000000100

    一般情况是直接用INT

  • float：float(m,d)

    • type: 单精度浮点型
    • m：表示长度或者位数
    • d：表示小数位数（小数位数是算在长度内的）
    • Eg: float(6,2)：表示该浮点数最大长度位6，且有两位小数，整数长度为 m-d, 即 4 位
    • 若长度超出6，如 12345，则不会被允许添加

  • double：double(m,d)

    • type: 双精度浮点型
    • m、d 同 float 一样

Q：单精度与双精度有什么区别？
能定义的长度不同，单精度为4个字节（7位有效数），双精度为8个字节（16位有效数）

  • decimal: decimal(m,d)
    • type: 定点型
    • m、d 同 float 一样

Q：浮点型与定点型的区别？
浮点型是近似值数据类型，存在误差，如 10/3 ≈ 3.33333 在数据库中可能是 3.33335。
定点型以字符串的形式存储数据，解决了浮点型带来的误差问题。
故，如果对数据的完整度十分敏感，那么采用定点型数据类型是合适的。

float, double 浮点数是近似值，其次，有效数字是指第一个非零数字开始的所有数字，无论其位于小数点左侧还是右侧。
当数值的有效数字超过7位，会进行四舍五入保留前7位数字，这也是单精度浮点数存在精度损失的原因之一。

数据类型：字符

  • char: char(m)

    • type: 字符串
    • m：表示字符串的长度
    • 一种固定了长度的，如果字符不够，则会用空格替代的字符串数据类型
    • 如一个长度为5的 char 字段，要写入 ‘汉字’ > ‘汉字xxx’（x 在这里表示空格占位）
    • 同 int 一样，若超出长度，则无法写入

  • varchar: varchar(m)

    • type: 字符串
    • m：表示字符串的长度
    • 不固定长度的字符串数据类型
    • 如一个长度为5的 varchar 字段，要写入 ‘汉字’ > ‘汉字2’；其中2表示该字符的长度
    • 同 int 一样，若超出长度，则无法写入

Q：char 与 varchar 的区别？
char 是固定长度的，可以有更快的读取速度，适合固定长度的身份证之类的;
varchar 是不固定长度的，相对于 char 而言，节约开销，比如名字，就适合用 varchar;

  • enmu: enmu('1', '2', ...)
    • type: 枚举型
    • 设置字段的取值范围

数据类型：日期

  • date: 日期型，结构为 YYYY-MM-DD

  • datetime: 日期时间型，结构为 YYY-MM-DD HH-mm-ss

数据表

CREATE TABLE

语法：create table 表名(字段1 数据类型, 字段2 数据类型);

Eg: create table student(id int, sname varchar(20));

CREATE TABLE：导入 （CTAS）

语法：CREATE TABLE 表名 AS SELECT * FROM 表

一步完成表的创建和数据插入，表结构会根据SELECT语句的结果自动生成字段名、数据类型，这些均由查询结果决定

适用场景：快速复制表结构和数据、基于查询结果创建临时表或统计报表等，无需手动定义表结构。

Q：和 INSERT INTO SELECT 相比？

  • CTAS 适用于快速复制表结构和数据、基于查询结果创建临时表或统计报表等，无需手动定义表结构。
  • INSERT INTO 适用于需要精确控制表结构，比如添加主键、约束、指定的更合适的数据类型等，或表已经存在时仅用于插入数据。

修改表结构：ALTER TABLE

语法：alter table 表名 关键字 修改的内容

  • add: 添加字段 alter table 表名 add 字段1 数据类型;
    Eg：ALTER TABLE actor ADD create_date DATETIME NOT NULL DEFAULT '2020-10-01 00:00:00';
  • rename: 修改数据表名字 alter table 表名 rename to 新表名;
  • change: 改变数据表字段信息 alter table 表名 change 旧字段 新字段 数据类型;
    • Eg: 将 name 更改为 rename: alter table 表名 change name new_name varChar(20);
    • 即没有做修改的部分也要完整的输出
  • drop: 删除字段 alter table 表名 drop 字段;

Q：MODIFY 和 CHANGE 的区别？

共同点：均可以修改字段类型
不同点：MODIFY不能修改字段名；CHANGE可以修改字段名

DML：INSERT INTO

语法：insert into 表名(字段1,字段2,...) values(val1, val2, ...);

除了数字外，其余数据都应被英文状态下的单引号包裹

若存在默认值default，那么在指明插入字段的情况下可以不管，若是没有指明字段的，则需要写全，否则会报错。

INSERT IGNORE（insert ignore）

INSERT IGNORE 是 MySQL 的一个特性，它会在插入数据时忽略主键冲突或其他唯一性约束冲突。

如果插入的记录会导致主键冲突（如 actor_id 已存在），该语句不会报错，而是直接忽略插入操作。

INSERT IGNORE是一个非常实用的语句，用于在插入数据时避免主键冲突或其他唯一性约束冲突，同时不会报错。这种方法非常适合处理批量插入数据时可能出现的重复记录问题。

DELETE：删除数据

语法：delete from 表名 [where 条件];

Eg: 删除goods表中gid为1的记录 delete from goods where gid=1;

  • 如果没有条件，则表示清空所有数据;
  • 可以进行多表连删
  • 子查询不被允许

TRUNCATE TABLE table_name;：清空数据表

Q：两者都做全表删除，那么 TRUNCATE 和 DROP 的区别？

A：DROP是逐行删除，TRUNCATE是将表删除再创建，速度快于DROP。

约束

  • NOT NULL：字段不允许为空
  • UNIQUE：字段不允许重复
  • PRIMARY KEY：主键，不为空+不允许重复的组合
  • DEFAULT：设置字段默认输出
  • FOREIGN KEY：外键，用的少
  • CHECK：保证字段中的值符合指定的条件。
  • INDEX：用于快速访问数据库表中的数据

约束：主键 PRIMARY KEY

主键：不允许重复、不允许NULL；一张表至多一个主键

  • 单主键：学号 INT PRIMARY KEY
  • 联合主键：几个字段列的组合而成，

约束：外键 FOREIGN KEY

语法：FOREIGN KEY(当前表即将成为外键的字段名) REFERENCES 外键目标数据表(目标数据表的主键字段名)

  • FOREIGN：foreign
  • REFERENCES：references

注意，如果删除表，那么应该先删除数据表B，再删除数据表A

一般情况下不太会用外键，因为外键会影响SQL运行速度，若用户量没那么多的，可以考虑

约束：自增长 AUTO INCREMENT

  • 不能单独使用，需要配合响应的约束条件

MySQL：需配合 PRIMARY KEY 或者 UNIQUE；
PostgreSQL：SERTIAL 或者 IDENTITY；
SQL Server：IDENTITY

约束：CHECK

保证字段中的值符合指定的条件。

也就是字段录入的前置条件

约束：INDEX

用于提高查询性能的数据库对象，它通过创建数据的快速查找结构，避免全表扫描，从而加快数据检索速度。

创建检索需要扫描

语法：CREATE INDEX idx_user_id ON orders(user_id)

  • CREATE INDEX：创建索引的关键字，用于告诉数据库对象
  • idx_user_id：给索引起的名字，命名规则一般为idx_字段名，方便识别索引对应的字段
  • ON orders：指定要创建索引的表名，这里是 orders 数据表
  • user_id：指定要为那个列创建索引，这里是 user_id 字段需要用到INDEX

如果涉及不允许重复，那么语法为：CREATE UNIQUE INDEX

如果涉及多个目标，比如经常需要查询 “2023 年用户 ID=10086 的订单
CREATE INDEX idx_user_time ON orders(user_id, order_time)
这个索引会先按user_id分组，每个分组内再按order_time排序，进一步加快多条件查询。

什么时候需要用到索引呢，超大数据量的情况下，如果有100万条数据，要从中找到制定的数据，

正常情况下是Select * From table Where user_id=123; 查询过程可能需要等待2~3秒，或许更久的情况

在这种情况下，使用索引会极大的增加查询速度。

FORCE INDEX: 強制索引

语法：SELECT * FROM table [FORCE INDEX(索引名称：idx_column)] [WHERE]...

Eg: select * from salaries FORCE INDEX(idx_emp_no) where emp_no=10005;

与CREAET INDEX是完全不一样的，它是SQL语句的一部分，是查询时的临时指令，强制数据库使用指定索引，用于解决优化器选择索引不当的问题

  • INDEXED BY idx_column：MYSQL的，和 FORCE INDEX 功能一样
    Eg: select * from salaries INDEXED BY idx_emp_no where emp_no=10005;

索引：删除

创建索引后，再不使用的使用别忘了清理掉：ALTER TABLE 表名 DROP INDEX idx_user_id;

若目标具有唯一约束：UNIQUE，执行ALTER TABLE 表名 DROP INDEX idx_user_id;后该字段将不在具有UNIQUE，且该操作会影响该表的user_id字段，将不在具有UNIQUE。
若目标具有唯一约束：PRIMARY KEY，执行ALTER TABLE 表名 DROP INDEX PRIMARY KEY，主键有特殊语法，不需要指定索引名

关键字

limit

  • limit N 返回 N 条记录，默认为前 N 条；
  • offset M：跳过 M 条记录，默认为 0 ，单独使用不起作用；
  • limit N,M：相当于 limit M offset N，从第 N 条记录开始，返回 M 条记录；
    LIMIT 5, 5 表示从第五条开始选取五条数据，但不包含第五条，也就是说是从第六条记录开始选5条

Q：写语句时常遇到“24岁以上”这样的条件，到底是大于等于还是只大于呢？

A：是只大于的，如果是大于等于，应该是“24岁及以上”

IS NULL、IS NOT NULL

语法：目标 IS NULL

NULL值无法通过常规的逻辑运算符判断，也就是无法使用如 age=NULL 这样的写法;

那么该如何判断空值呢？

Eg: 现在运营想要对用户的年龄分布开展分析，在分析时想要剔除没有获取到年龄的用户，请你取出所有年龄值不为空的用户的设备ID，性别，年龄，学校的信息。

LIKE

  • 通常和通配符%、_配合使用，做模糊查询
  • 只能用于有引号的目标

Eg：现在运营想查看所有大学中带有”北京”的用户的信息(device_id,age,university)，请你取出相应数据。

通配符

  • %：匹配多个字符；北京%表示北京大学，北京医院，北京车站等等
  • _：匹配一个字符；如上即可明白
  • 正则：https://www.runoob.com/sql/sql-wildcards.html
    • WHERE name REGEXP '^[GFs]': 名字以 G、F、s开头的
    • WHERE name REGEXP '^[A-H]': 名字在 A~H 这个区间内开头的
    • WHERE name REGEXP '^[^A-H]': 不以 A 到 H 字母开头

排序 ORDER BY

  • ASC：升序（默认值）
  • DESC：降序

语法：SELECT * FROM TABLE_NAME [ORDER BY 目标字段 ASC]

Q：多列排序如何处理？

A：GROUP BY 字段A ASC, 字段B DESC

转移查询：INSERT INTO SELECT

  • 将一个表的数据复制到另一个表
  • 目标表中任何已存在的行都不会受到影响

注意：【目标表中任何已存在的行都不会受到影响】是有前提的

Q：前提是什么？

A：需避开表的约束

若为空表，那么无需在意，只需将目标字段转移过来即可，
若不为空表，则需要注意，如主键是否重复了，如果主键数据不需要，则从复制字段中剔除。

  • 空表： INSERT INTO ccc SELECT * FROM aaa; 会将aaa表数据原封不动的输入到ccc表
  • 非空表：若继续执行空表时的操作，则会报错，因为主键约束，所以需要避开，那么：INSERT INTO ccc (cName) SELECT aName FROM aaa; ，执行完毕后，表中将多两出条数据，印证了“目标表中任何已存在的行都不会受到影响”
